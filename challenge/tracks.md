# Tracks

Pick one track. We evaluate all tracks with the same basic lens: judgment, usefulness, clarity, and how you handle ambiguity.

## Track A: Fictional Domain Packet

Read [domain-packet.md](domain-packet.md), then use [sample-data/product_usage_events.csv](../sample-data/product_usage_events.csv).

Choose this if you want the fastest start while still working in a slightly unfamiliar domain. The signal here is how you digest context, handle messy data, notice suspicious records, and turn a vague teammate ask into a useful artifact.

Good submissions might include:

- a compact notebook that explains what changed and what looks suspicious;
- a simple dashboard for comparing workflows;
- a CLI that prints a short weekly health summary;
- a tiny page that recommends what to investigate next;
- a small checker that flags records or metrics that should not be trusted blindly.

## Track B: Bring Your Own Domain

Use a small public or synthetic dataset from a domain you care about.

Choose this if you want to show taste, curiosity, or domain instinct. The signal here is what question you pick, how you bound it, and whether the result would help someone.

Your README should make the domain understandable to someone who knows nothing about it.

## Track C: Tiny Model / Eval

Use a small model, prompt, heuristic, or evaluation workflow.

Choose this if you want to show how you work with models or AI systems. The signal here is not model complexity. It is whether you can frame a practical question, collect or create enough data to test it, and sanity-check the output.

Good submissions might include:

- a tiny eval comparing two prompt strategies;
- a simple heuristic/model with a few clear caveats;
- a script that gathers public data and produces a useful prediction or ranking;
- a small workflow that uses an existing model and checks where it fails.

No paid cloud GPU is expected. If you use paid tools, keep it tiny and explain why.
